# 可迁移的功能约定

这是部署者可选择合并到其工作区 AGENTS.md 的模板，整理日期为 2026-11-16。它只描述本套扩展的操作边界，不自动加载、不修改全局规则，也不替代当前会话的工具 schema、权限和用户指令。环境准备见 [ENVIRONMENT.md](ENVIRONMENT.md)，浏览器准备见 [BROWSER-SETUP.md](BROWSER-SETUP.md)。

## 路径和能力发现

- `${WORKSPACE_ROOT}` 表示部署者实际工作区；`${DSH_PROFILE_DIR}` 表示当前 Harness profile；`${BUNDLE_ROOT}` 表示本套件解压或源码根目录。本文 `${...}` 是说明记号；发布源码的 `__DSH_SUITE_*__` token 由套件 `scripts/prepare.mjs` 根据部署模板生成本地副本，不要求手改源码。不要混用两种记号，不将本地配置和 prepared 目录提交公共仓库。除非明确写成 PowerShell `$env:...`，不表示 shell 或 YAML 自动展开变量。
- 当前工作目录与 Harness 安装目录分别确认，不按目录名推断。使用 `load_workspace_dependencies` 发现运行时 Node、pnpm、Python；调用前确认本会话确实暴露相应工具。安装记录和 README 不能代替当前可用性验证。
- 查询 Harness 的功能、插件、配置、工具或 Cordis API 前加载 `dsh-doc`。查实时接口时先发现 Inspect provider，再使用其公布的精确 schema；不要猜 API 或从其他版本搬用内部接口。
- 只在现有权限和授权范围内工作。文件沙箱、审批、子代理深度与工具可见性由运行环境决定；遇拒绝先查实际权限，不绕过限制、不把单一权限模式中的失败说成插件损坏。
- 若工具通过 PTC 暴露，使用该环境提供的执行器和生成 SDK；若为直接工具，则按直接 schema 调用。不在承载当前调用的执行器内热切换工具呈现插件。

## 执行与协作

- 主代理维护目标、上下文和验收；可独立的新增工作在当前允许深度内用原生 `subagent` 派发。共享文件按不重叠范围分工，合并前读实际结果并验证。
- 独立任务使用原生 `subagent`，仅提供需要的任务材料。不用普通聊天入口 `agent_chat_create` 派任务，不用 `subagent_fork` 绕过无父历史任务约定。普通新聊天仅在用户明确要求时使用其合法入口；工具不可用时报告实际限制。
- 默认使用后台 API、脚本、CLI、headless 或持久终端，不启动可见应用、不抢焦点、不操作既有标签页。只有用户本次明确要求界面操作时，才操作点名程序并在任务结束后停止。
- 已授权且可回退的动作继续推进，外部写入先核对目标。提交结果不明时查原任务，不以新 ID 重复提交。共享账号写入按事务串行。
- 开工简述阶段，阶段完成报告可验证结论；以真实文件、页面和日志验收。报告区分源码检查、模拟回归、真实工具调用、真实界面验收与异机验证。

## 浏览器调用约定

- 默认网页任务使用 Harness 专用 `mcp__playwright_browser__*`。它有自己的持久 profile，不代表用户日常 Chrome；其当前页操作不能由多个代理并发切换。
- 显式 pageId 的后台任务使用 `mcp__background_browser__new_page` 创建本会话新页，后续始终传该 pageId；用 `background_browser_pages` 查自己页，不用全局 `list_pages`，不认领旧页或父子会话页面。需要临时存储分离且已有 hub 时，可用 `background_browser_open({url,storage:"session"})`；`shared` 明确复用共享持久 profile。两套 MCP 参数不得混用。
- 仅当用户明确要求“我的／日常 Chrome”时使用 `google_chrome_connect` → `google_chrome_open` → `google_chrome_read/evaluate`。保留返回的 pageId，只操作自己新建页，不自行启动或重启 Chrome、不添加调试端口、不复制登录态、不按标题或进程名关闭浏览器。
- 页面归属只是调用路由检查；临时 browser context 只是存储分离，均不是进程、操作系统或账号安全隔离。同一共享后台 profile 内、以及日常 Chrome 自己的 profile 内，同源账号数据仍跨任务共享；这不表示两个独立 profile 互通登录态。
- 第一次启动失败即停止该启动路线，不换参数反复拉起。登录、验证码、站点风控、无头限制如实说明，给出最小人工登录步骤；未获授权不切到日常 Chrome 或桌面接管。相同问题连续三次无进展、或单阶段五分钟无可交付结果时，整理证据并说明阻碍。
- Harness 页面返回 401 时，使用部署者正常启动和认证入口；不关闭认证、不复制凭据。status 可读或工具已注册不等于网站已登录。

## 功能相关的结果与维护

- 美术工具箱任务完成并验证后，用 `art_toolbox report` 回报真实文件及限制；普通会话的同类成果用 `art_toolbox import` 登记。查旧成果先 `repository` 再 `detail`。改版保留原件并关联 `parentId`，归档不冒充文件删除。
- ComfyUI 工作流用 `comfy_workflows` 保存原始 JSON、来源会话、版本与逐节点调整说明。结构验证不代表效果通过；安装工作流不自动推理或下载模型。停机遇任务忙或队列未知时，不自行强制停止。
- 公司媒体请求优先 `drock_media`，保持普通聊天模型。按用户数量创建任务，稳定 `requestId` 防重复付费；`generate` 未完成则对同一任务 `wait/status`。插件已有结果预览时不另做第二份预览；提交成功不能报告为生成完成。不要为验收自动付费或静默换默认模型。
- Pinterest 任务先加载对应技能；使用队列绑定用户授权的目标，研究者只读审图，主所有者串行保存。期限、研究者上限和结果数量以当前技能及工具返回为准，不虚报收藏。
- WorkBuddy 桥只复用部署者已具备的本地专家资源；配置预览不迁移凭据、不代表连接器已认证，也不自动获得原平台生成额度。
- 新增、修复、迁移、升级或停用能力后，更新对应专项说明和索引，记录用途、入口、验证范围与限制。不把个人项目、安装流水账、凭据、账号信息或个人维护定时任务写入公共约定。
- 插件安装和配置用 Harness 正式管理入口；不手改整个 profile，不删除仍被 link 安装引用的源目录。按管理器 `application/nextStep` 决定是否需要完整重开。Host 源码更新不承诺热生效；Client 热更新还取决于匹配源码构建监听和真实客户端加载。
